## Coverage ceiling

About 1,050 unverified function lines are beyond Verus’s current reach: inline assembly (~330), FFI, syscalls, and function pointers (~230), `UnsafeCell`, volatile access, `transmute`, and `from_ne_bytes` (~330), atomics and the panic handler (~100), and raw pointers from C callers (~100). These categories overlap. Keeping upstream’s exact code, identical hot-path codegen, and no new soundness risk puts coverage near a soft ceiling.

Possible relaxations and rough gains:

- Done: `panic!` aborts now format through `abort_fmt` (33 more functions verify; aborts lose their file and line).
- Allow codegen drift for cold raw-pointer permissions: ~40 functions and ~350 lines.
- Rewrite cold iterators: ~5 functions and ~80 lines.
- Allow hot-path codegen changes after Dan’s benchmarks: ~10 functions and ~80 lines.
- Trust per-call permissions for pointers from C callers: ~15 functions and ~100 lines. This adds soundness risk and is not recommended.

Other tools could cover much of the remainder: Islaris for inline assembly, RefinedRust/Iris for `UnsafeCell` and raw pointers, Kani for function pointers, and GenMC/loom for weak memory. Connecting their results to the Verus contracts would require documented, reviewed translations.

### Theorem premises

All sixteen theorems are in the code. [THEOREMS.md](THEOREMS.md) records where each statement is narrower than the allocator’s behavior and which trusted premises it uses. The active lanes are:

- **Uniqueness:** `create_heap_for_thread` proves a new heap’s `wf`, including `tokened` and `home_ok`; `Heap::create` and `create_detached` are verified using `Meta::alloc_raw` and typed permissions. Verified `swap_hdrs` and `free_caches_in` replace stale-permission writers. `cache_ptr` is verified except for `home_ptr_at`’s address computation. `Heap::theorem_uniqueness_held`, `theorem_uniqueness`, and `theorem_uniqueness_apart` state uniqueness for held slots, one heap, and two heaps. Existing-heap accessors still assume `wf` because ghost state does not survive between calls. Trust also remains in `destroy`, whose verification shifts LTO inlining of `Meta::free`; `init_fields`, `mark_bound`, `node_set_arena`, `axiom_fresh_stack`, `axiom_list_bound`, and `node_next`’s chain. Live blocks are modelled: the allocation cores hand the caller the block’s `heap::live::Live` token (a slot token, or a huge `RunToken` from the run authorities the huge lock’s invariant now holds), every free core consumes one, `Live::theorem_apart` proves two live blocks disjoint and `Heap::theorem_uniqueness_live` a cached slot no live block. The C boundary is one trusted step, `heap::live::axiom_c_claim`, called once per C free or realloc; `class::axiom_free_token`, `huge::mint_allocated` and `vspec::huge::axiom_owned_run` are gone, and `axiom_moved_block` takes the disjointness the tokens prove as a precondition.
- **Zeroed memory:** `mallocx_zeroed`, `alloc_with` and `calloc_usable_zeroed` now cover the whole usable size; `rallocx_zeroed` ties the copied prefix `k` to a slot’s class size and covers the new block’s usable tail. `vspec::zero::theorem_zeroed_memory` states that every byte from `p + from` to the usable end reads zero. `Meta` gets zero tokens from `Unbacked::commit` and `fresh_zero`; slab zero picks use `axiom_fresh_slots_zero` and `axiom_discarded_slots_zero`, which require the slab’s `Fresh` or `Purged` state under the class lock and its slots’ uniqueness tokens. `rallocx_zeroed` also ties `k` to a huge `p`’s old usable size through its token (`k == min(blk.len(), size)`, with `old_size_or_keep` ensuring `old == blk.len()`; under the `free` contract, as the token comes from `axiom_c_claim`). Still open: use an `Unbacked` token to establish that pages past the huge mark were never written, and have `purge::Batch::flush` return zero tokens from eager `MADV_DONTNEED` to discharge the `Purged` premises.
- **Metadata integrity:** `heap::theorem_metadata_integrity` now separates user blocks from `Meta` free-list link words and the `Shared` static, using the trusted `Reserved::is_apart_from_static` fact for the static. TLS can occupy a malloc-allocated thread stack, so the theorem does not exclude it. Still open: use `WordPerm`s to place bitmap words in `SlabTable::meta_ok`, cover the partial last word as a whole word in metadata, prove slab-set placement through `SetTable::new` and `Set::in_table`, and add permission-carrying atomic wrappers for descriptor and owner-word writes.
- **Usable sizes:** `vspec::usable` states a block’s usable size: `usable_is` for an allocation of known size (the class size, or the request rounded up to whole pages), `usable_of` for a query of a live block. `usable_size`, `malloc_usable_size`, `sallocx`, `xallocx` and `free_usable` ensure `usable_of`; `malloc_usable_stored`, `calloc_usable_zeroed` and `realloc_usable_stored` return the `Stored` token of `store_usable` with `usable_is`; `nallocx` and `mallocx` share `jemalloc::nalloc_usable`, using `class_for`’s functional spec (`spec_class_for`, the smallest serving class); `theorem_usable_consistent` ties a slot query to the allocation. For a huge run the allocating entry points read the size back with the run token `alloc_huge` returned, whose usable bytes are the request rounded up to whole pages (the former `axiom_owned_run` is gone), and `free_usable` also states the freed block’s token’s usable bytes. Still open: tie a query of a huge run (`malloc_usable_size`, `sallocx`, `xallocx`) to its request size (the queries take no token), and state the 0 that `challoc_malloc_usable` stores for NULL (`Regions::wf` does not rule out a slot at address 0).
- **Guard pages:** Done for slabs. `Regions::is_slot` excludes the process's guard slabs (`layout::guard_slab`, fixed per class by `table::axiom_slot_loc`), so every `fits` and every `free_target` carries the exclusion; `heap::theorem_guard_pages` and `theorem_guard_free` state it. The unsized free paths learn it from the bit test: `is_set_unchecked` reads the word through `vspec::word::load` inside its invariant, where `bitmap::guards_ok` keeps a guard slab's bits clear; the sized path's `GuardTest` is proved equal to the table's test. Machine code is unchanged on x86_64 (aarch64 is checked at integration). Still open: huge runs are covered only at the huge lock invariant (`huge::Inner::theorem_run_guards`); `alloc_run` now returns the run's token, so state `theorem_run_guards` per result over it, and model the fallback mode's re-commit of stale `PROT_NONE` guards.
- **PAC:** Done. `sign`, `auth`, `strip`, and `mask` require `pac_available()`, meaning every CPU the process runs on implements FEAT_PAuth. `pac::available()` establishes it; `Shared::init` proves the `Shared::wf` premise `pac_mode() ==> pac_available()`, which hot paths carry as ghost-only requirements. One trusted fact in `sys/auxv.rs` links both `HWCAP_PACA` and `HWCAP_PACG` in `getauxval(AT_HWCAP)` to system-wide PAuth availability on aarch64. Machine code is unchanged.

### Theorem candidates

These candidates would extend the guarantees beyond the theorems in [THEOREMS.md](THEOREMS.md) (theorems 8-15 below are done; theorem 16 is stated and partly proved).

- **No syscall on the fast path:** Done, theorem 8 in [THEOREMS.md](THEOREMS.md). Every function that can enter the kernel requires the opaque capability `sys::may_syscall()`: the raw syscall seams, every trusted body that reaches the kernel, and their callers: about 404 contracts on the integration branch (385 at the lane commit; the live-block `_block` cores and the functions of theorems 13, 15 and 16 that reach the kernel added the rest, with `Set::ensure` and `Inner::ensure_sets`, which lacked it). Only `extern "C"` entry points and `abort_fmt` grant it, and a test checks that in the source. The verification-only `theorem_no_syscall_on_fast_paths` calls the `malloc`, `free`, `free_sized` and `challoc_free_usable` fast paths without it, so they make no system call. A counter or token threaded through the slow paths would have changed hundreds of signatures. An `opens_invariants none` mask would have needed no new requires, but vstd specifies `Option::map`, `?` and the atomics with mask `any`. Still open: the `calloc` lookup before its pop (`api::shared` and `heap_for_thread` may initialise or create a heap), `realloc`, and `free_aligned_sized`'s hint, which the witness does not call.
- **The fast path never hangs** (theorem 9 in [THEOREMS.md](THEOREMS.md)): no function the fast branches of `malloc`, `free`, `free_sized`/`sdallocx` (flags 0) and `challoc_free_usable` call can acquire a lock, and each terminates. Each fast-path function declares an invariant mask (`opens_invariants none`, or the bitmap words' namespace for the unsized free's bit test) and `RawLock::lock`/`Lock::lock` declare `any`, so Verus's mask check rules out any call chain from them to a lock; that the entry points' fast branches call only those functions is read off their bodies. No `exec_allows_no_decreases_clause` was on these paths (the nine left are all slow-path waits). The paths are loop-free apart from the trusted `cached_recently` (at most three compares); the step bound is read off the code, since Verus proves termination but has no cost model. vstd gives `?`, `Option::map`, the array-to-slice coercion and `core` atomics the default mask `any`, so eight `?`s became `let ... else`, one `map` a `match`, and four array reads and the `multi_arena` load go through `vspec::slice::array_get_unchecked` and `vspec::atomic`, and the owner-word load through arena isolation's `load_owner` (machine code identical on x86_64). Still open: `calloc` and `realloc` (`api::shared()` may wait on init; `heap_for_thread` may create a heap), `free_aligned_sized` and flagged `sdallocx` (`class_for` is unmasked), and a step count Verus can check.
- **No leak on thread exit** (theorem 10, [THEOREMS.md](THEOREMS.md) section 10): `Heap::flush_all`, which `destroy` runs first, ensures every home and `others`-node header empty (`Heap::drained`) and a ghost released log (`CachePerms::released`) extended by exactly the `(class, address)` pairs those headers held (`Heap::held_all`); `Heap::flush` states the same per cache for any `n`, and `Shared::release_routed` now ensures it took every batch token out of the bag through `release_owned`. Ghost only; machine code unchanged. Still open: verify `destroy` itself (its `free_caches` still writes the plain `caches` field), make "`toks` holds no token past `len`" and "every owned header is a home or node header" invariants of `Heap::wf`, and add `no_duplicates` to the log's new entries from theorem 5.
- **Shuffle is a permutation** (theorem 11 in [THEOREMS.md](THEOREMS.md)): `shuffle_zero` ensures `permutes` (the multiset of the batch is unchanged) for every `rng` value, and `theorem_shuffle_permutation` derives equal counts, membership and duplicate-freedom. Randomness is out of scope. Still open: name the pre-shuffle batch in `claim_random_zero`'s `ensures` (needs a ghost return value).
- **Zero-on-free** (theorem 12 in [THEOREMS.md](THEOREMS.md), release-time form): With `zero_on_free` set, every free path gives up a slot (cache push or bitmap release) or a huge run (`free_huge`) only while holding a `Zeroed` token for its bytes (a slot's class size; for a run, whole pages from its start as `Huge::spec_run_usable` admits, which the code makes its whole usable size): `zero_slot` and `zero_huge` return the token (through `write_zero`, machine code unchanged), and `heap::zero::theorem_zero_on_free` and `theorem_zero_on_free_huge` are discharged at each release in `Heap::free_slow_in`, `heap::free_direct` and `Heap::free_huge`; the fast pushes provably decline under `PUSH_ZERO`. Still open: hand `zero_huge` the run token the freeing path holds, so `Huge::usable_size` names the descriptor's usable pages and the huge token provably covers them all; make release coverage mechanical (a ghost `Zeroed` argument on `Shared::free_direct`, `Shared::free_huge` and `push_cache`); carry the token with the slot (per cached entry above the zero prefix and per clear bitmap bit), so a pop or claim of a slot freed under `zero_on_free` states it zero at hand-out.
- **Fork safety** (theorem 13 in [THEOREMS.md](THEOREMS.md)): `fork_prepare` ends holding one `lock::LockHeld` token per lock of the fork lock list, and `fork_release` (the parent and child handlers) hands every token back through `RawLock::unlock_held`, ending with none; the child rewrites the background state only under its token and keeps its lock invariant. Premises: the futex mutex contract, the atfork handoff (`api::axiom_fork_resumed_state`, `axiom_fork_resumed`), a frozen arena table under the creation lock (`api::arena_held`, `count_held`). Still open: prove the nesting order, and the list's completeness (the test `fork_lock_list_matches_the_source_tree` checks it).
- **Arena isolation** (theorem 14 in [THEOREMS.md](THEOREMS.md)): A slab slot belongs to the arena its group was handed to (`class::slab_owner`, fixed by `take_group`'s owner-word store and read back by every owner load, two trusted wrappers). `ClassState::plan` reserves only in slabs the arena owns (the class lock invariant now holds `owns(s) ==> slab_owner == arena`); `release_owned` releases only the arena's slots and `release_with`, `Shared::free_direct` abort (`wrong_arena`) otherwise; `release_routed` follows the owners and its termination is now proved. Still open: carry the owner from the picks through `finish` to `claim`'s and `malloc`'s results, and tie a huge run's descriptor arena to `alloc_run`'s argument (live-block run token).
- **Re-entrant heap registration** (theorem 15 in [THEOREMS.md](THEOREMS.md)): The TLS slot is a ghost `sys::tls::TlsSlot` token. `ThreadKey::set` requires a sentinel in the slot, and at a sentinel `heap_for_thread_in` returns `None` and leaves the token unchanged: no slot write and no `Heap::create` call. `existing_heap_in` takes the token shared and returns `None` at a sentinel. The `pthread_setspecific` wrapper models nested entries as these cores holding the lent token. Still open: `Heap::create` making no call that can allocate is checked by inspection, not by Verus; the theorem does not state that no allocator lock is held across `ThreadKey::set`.
- **No allocator lock across external calls** (theorem 16 in [THEOREMS.md](THEOREMS.md), stated, partly proved): Callbacks, `malloc_message`, and `fwrite` reached from `malloc_stats_print` or `malloc_info` run while the calling thread holds no allocator lock. These calls can allocate, so holding a lock could deadlock. Every report call out of the allocator is in `api::print::emit`, which requires the ghost permit `Unlocked`; only the three entry points mint one (`axiom_unlocked`), and the report's `Sink` holds it. That the permit's holder holds no lock rests on premises that a source test checks (the report code takes no lock, guards stay in their scope, only the fork handlers take a bare `RawLock`). Two tests re-enter the allocator from every call out, so a lock a report takes, held across a call, fails them. No path calls out with a lock held. Still open: a ledger of held locks that Verus checks needs a `Tracked` token through `Lock::lock` and every path to it. The lock-order candidate below needs the same ledger, so the two could share it.
- **Exact stats:** `mallinfo`, `malloc_stats`, and mallctl statistics equal the true sums over live blocks. This needs a live-block accounting model: the `Live` tokens model each live block, but nothing sums them.
- **Bad input** (done, the B column; [THEOREMS.md](THEOREMS.md), "Bad input"): bad input aborts or gets the documented error, except a huge run's size on a sized free (unchecked, as in jemalloc) and an ABA free (undetectable). Proved: pointers that are not block starts (foreign, misaligned by `theorem_free_target_aligned`, interior by `Live::theorem_interior`) abort; a slot freed with another class's size or a bad alignment aborts (`hint_ok` on `free_sized`, `free_aligned_sized`, `sdallocx` and the sized `delete`s, from the completeness of `Regions::slab_slot` and `classify`; for a live slot, as a non-live one rests on `axiom_c_claim`); `MALLOCX_TCACHE` ids of `MAX_TCACHES` or more abort (`tcache_checked`, `bad_tcache`); a non-zero non-power-of-two `align_val_t` gets no block. Excluded by the C contract (`axiom_c_claim`), not proved: stale and double frees of slot or huge page starts, and interior page starts of huge runs; the run-time checks stay. Still open: arena and cache existence for `MALLOCX_ARENA` and `MALLOCX_TCACHE` ids below the limit; the queries' stale-slot and interior-page aborts; and a huge run's size against the sized frees' hint, which the code does not check either.
- **Huge free extents are maximally coalesced** (done, theorem 17): `huge::Inner::wf` now states that no two free descriptors touch (`coalesced`) and that every page of a free extent is in the free-page bitmap (`free_marked`); `Inner::theorem_coalesced` states it ([THEOREMS.md](THEOREMS.md), section 17). `find` proves it returns fresh pages only when no free extent touches the mark, `free_before`/`free_after` find every free neighbour, and `take`, `free_run` and `purge_extent` keep it. No counterexample: alignment holes at the mark cannot touch a free extent. Ghost-only. Still open: the converse of `free_marked` (a free bit belongs to a free extent), which `audit` also checks.
- **Pressure never lengthens decay** (done, theorem 18): For a fixed effective cgroup limit and configured period, higher usage never gives a lower band (`lemma_band_monotone`) nor a longer effective decay period (`policy::theorem_pressure_never_lengthens_decay`), over exact specs of `usage_ppm`, `band` and `effective_decay_ns`. Open: changing limits, and the `Policy` atomics round trip (`Policy::apply` then `Policy::band`) under concurrent evaluation.
- **Purge never discards live data** (done, theorem 19; for huge runs, slabs stop at the class lock): every `purge::Batch` carries a ghost predicate `free`, fixed by its maker, and `discard` hands `madvise` only bytes it admits. Huge batches admit pages outside the run-page authority, so `RunToken::theorem_purge_apart` and `Live::theorem_purge_huge` prove no live block's byte is discarded. Class batches admit slabs the arena's class lock records as idle (`Fresh`, `Empty`, `Purged`). Still open: tie idleness to the slot tokens, which needs the descriptor's lock-free `live` counter as ghost-tracked state (credits minted by `take`, deposited by the claim's `fetch_or`, released by `fetch_and` and `sub_live`) through the claim and release paths; and theorem 6's purge premise (eager discards minting `Zeroed` tokens held per `Purged` slab or extent, and a ghost link from `LAZY_EVER` to the lazy batches).
- **MIB round-trip:** If `name_to_mib` succeeds, `mib_to_node` returns the same node and indices. `mallctlnametomib` returns `EINVAL` for a short buffer, whereas jemalloc returns a partial MIB; keep that compatibility difference explicit.
- **`MALLOCX_TCACHE_NONE` bypasses thread caches:** Allocations and frees with this flag neither take nor insert a slot in any heap cache. Valkey’s defragmenter relies on this behavior.
- **Lowest-address huge placement:** `Huge::find` returns the lowest page that fits the requested size and alignment. The maximal-coalescing proof can simplify the free-extent cases.
- **Lock order is acyclic:** Every blocking lock acquisition has a higher rank than each lock the thread holds, ruling out lock-order deadlocks. This needs a ghost set of held locks through every guard and must cover the nesting order documented by `fork_prepare`.

- **Config parsing is faithful:** `load` returns numeric fields within their declared ranges, the pair tokenizer accounts for every source byte as a token or an `Issue`, and each key takes the last well-formed value from the highest-priority source. May be false today: input past 4,096 bytes can end mid-pair, and an unterminated quote can swallow later pairs without an issue. `config.rs` is largely verified, so this is a cheap candidate.
- **A background-thread request is never lost:** Outside the interval between `main`’s `requested()` check and its exit, `REQUESTED` implies a thread is present; at most one thread exists. May be false today: a request can race the thread’s exit. Extend the loom model; medium effort.
- **Mallctl write/read contract:** An error leaves state unchanged; when both `oldp` and `newp` are supplied, the old value is read before the new value is applied; reads write at most `*oldlenp` bytes; and `mallctlnametomib` writes nothing on failure. May be false today: `arena.<i>.dirty_decay_ms` may change on error. Cheap to medium effort.
- **Cgroup policy round-trip:** After `Policy::apply(b)`, `Policy::band() == b`, and `headroom()` implies the `Low` band. May be false today: `Scaled(0)` reads back as `Low` at the 70% edge. Cheap effort.
- **Double-free detection window:** State exactly when the run-time checks abort a free of a slot among the top four cache entries or one whose bitmap bit is clear. The contract must also state where detection is narrower than `docs/hardening.md`, including `realloc` of a still-cached freed pointer; medium effort.
- **Seal targets stay inside challoc’s reservations:** Every range returned by `never_committed` and passed to `mseal` lies inside challoc’s mappings and outside the class, huge, and metadata regions. This needs reservation arithmetic from `reserve_owning`; cheap effort.
- **jemalloc size contracts:** A sized free returns normally only when given the block’s real class or run size; `nallocx` returns zero exactly when `mallocx` would reject the size or alignment. May be false today: huge runs and very large alignments may violate these claims. Cheap to medium effort.
- **Fragmentation bounds:** Class waste is below `max(QUANTUM, n/4)` for `n <= MEDIUM_MAX`, per-class slab tail waste is below one slot, and a medium aligned allocation’s usable size is below twice `max(size, align)`. These bounds appear to follow from the size-class and alignment arithmetic; cheap to medium effort.
- **Deterministic address-ordered reuse:** Claims take the lowest free bits, `Meta` reuses the last freed block in a bin, and without `slot_randomize`, a refill leaves the lowest slot on top. This is a cheap candidate; the heap’s RNG is not reseeded in a fork child.
- **`posix_memalign`, `pvalloc`, and `operator new` contracts:** `posix_memalign` leaves `*out` unchanged on failure and returns a fitting block on success; `pvalloc` rounds to the page; throwing `operator new` never returns NULL. These extend gap 4 and are cheap candidates.
- **Purge batches are well formed:** Every discarded range is page-aligned, non-empty, and inside a class or the huge region, never metadata. This needs to carry region bounds through batch construction; medium effort.
- **PAC entry binding** (research): A tampered or replayed cache entry is rejected. This needs a modifier binding the entry and class, with a fast-path cost, plus a trusted fact about authenticating an unsigned word; settle the design before attempting the proof.

- **No block at address 0:** `Regions::separated` states that every class base and the huge base are non-zero; prove that `is_slot` and `is_huge_block` therefore imply a non-zero address. `try_reserve` already ensures a non-zero reservation, so this is cheap and closes the `malloc(0)`, NULL usable-size, `operator new`, and `sallocx`/`xallocx` gaps.
- **Failure strands no resources:** After an allocation or construction step fails, everything it acquired remains reachable from allocator state or reusable. May be false today: `Arenas::build` abandons a reservation when `Arena::init` fails, and `Arena::init` does not release its set table when `SetTable::new` fails. Medium effort per constructor.
- **A valid free survives resource exhaustion:** Freeing a live block with valid arguments never aborts solely because heap, cache, or TLS registration allocation fails. May be false today: a thread’s first free can create a heap and abort if `pthread_setspecific` fails. Medium effort.
- **Cgroup pressure counts the ancestor under pressure:** For a stable hierarchy, the chosen band is at least the band implied by each ancestor’s usage against its own limit. May be false today: a parent at 95% of its limit can read as `Low` when usage comes from a small leaf. Medium effort.
- **Cgroup sample clock never goes back:** Sample timestamps never decrease; a decision uses usage no more than one sample interval plus one tick old, or marks it stale. May be false today: an older `now` can move `sampled_at` backward, and a failed read can advance the timestamp while retaining old usage. Cheap to state.
- **Stats identities and epoch coherence:** Every snapshot satisfies `resident >= active >= allocated` and `mapped == resident + retained`; arena figures sum to the totals, and an epoch write collects both from the same snapshot. May be false today: concurrent epoch writers can separate per-arena stats from totals. The identities are a cheap first step toward **Exact stats**.
- **Cache flush completeness:** After `flush_all`, every home cache and others-node cache in the heap is empty. This would show that `tcache.flush`, `thread.tcache.flush`, and disabling the tcache strand nothing in a live heap; cheap to medium effort.
- **Explicit tcache lifecycle:** `tcache.create` returns an unused ID below `MAX_TCACHES`; after `destroy`, `get` returns `None` and every cached slot has been released; `flush` leaves the cache empty. The lifecycle is unverified today; medium effort.
- **THP advice placement:** With `thp:never` on a THP kernel, `NOHUGEPAGE` covers the class and metadata reservations before any byte is committed; every `HUGEPAGE` range is aligned and inside a class or the huge region. May be false today: masked `/sys` can make the kernel mode read as off, suppressing `thp:never` advice. Medium effort.
- **C++ nothrow new contains handler exceptions:** If `new_handler` throws during a nothrow allocation, every nothrow form returns NULL without letting the exception escape. May be false today: the handler is called without a catch. This needs a C++ test and a small catching boundary rather than a Verus proof.
- **Cache routing:** A pop comes only from the home cache, the others node keyed by the requested arena, or an explicit tcache; the foreign node is never popped, and others keys are distinct from each other and the home arena. Cheap to medium effort. This does not claim that home caches contain only home-arena slots: sized frees can put other arenas’ slots there.
- **Fork reclaims orphaned caches** (design target): After `fork`, slots cached by vanished threads become reclaimable by the child without touching live blocks. Hard; design section 9 currently leaves those slots marked until the child exits.
- **Realloc keeps whenever it can** (low priority): `realloc(p, size)` returns `p` exactly when `size` maps to `p`’s class or run, so `realloc(p, malloc_usable_size(p))` never moves. This is a cheap candidate.

Research, likely beyond Verus:

- **Bounded memory:** Bound RSS by a function of live bytes. This needs a model of retained and committed memory.
- **Purge within the decay time:** Return eligible memory within the decay time. This is a liveness property of the purge thread and its wake-ups.

The gap list already tracks realloc contents and the rest of the failure semantics (rows 6, 16, 17 and 23-25); the live-block model, the huge kept bound, bad input and `errno` (gap 2) are done, and purge never discarding live data is done for huge runs (above).

### Weak memory and external models

- Carry out the weak-memory checks in [WEAKMEM.md](WEAKMEM.md). Verus assumes sequential consistency and does not establish that the shipped `Relaxed`, `Acquire`, and `Release` orderings suffice. #72 fixes the background purge wake-up’s startup race; its weak-memory form (WEAKMEM.md P3) still needs a fix.
- Fix the heap's cache handles, which Miri rejects under both Stacked and Tree Borrows: a raw pointer into `Heap::caches` from `cache_ptr(&mut self)` is used inside later `&mut self` methods ([MIRI.md](MIRI.md), finding 1). Verus's permissions do not model Rust's aliasing rules, so the proofs cannot catch this.
- Model the kernel and CPU boundary before reducing trust in assembly and syscall wrappers, including `sys/raw.rs`’s syscall functions, TLS, PAC, and CPU instructions. The kernel contracts for `mmap`, `madvise`, and `mprotect` remain premises.
- Use a liveness-capable model for lock waits and `claim_with`. The Verus theorems state partial correctness: they describe calls that return.

### Uniqueness: slot tokens

`SlabTable::new` creates one `GhostSetAuth<int>` per class table. Its elements are slot addresses; bitmap padding bits have no element. A `GhostSubset<int>` or `GhostSingleton<int>` token identifies a held slot, and two tokens from the same authority cannot contain the same address.

A separate marker authority records whether each bitmap bit is fresh or initialized. The commit lock holds initialization markers for slabs it has not handed out. `AtomicBitmap::init` exchanges a slab’s markers as it initializes its words and padding bits. A claim needs the resulting persistent markers, which establish that it is claiming initialized slots.

A slot’s token moves with its ownership:

- A clear bitmap bit’s token sits in its word’s `AtomicInvariant`, alongside the word permission.
- A successful claim moves the token to the claimer. `finish` returns tokens keyed to the pointers it writes.
- A cached slot’s token sits in `CachePerms::toks` under its stack entry. Verified refill, pop, push, flush, and rebuild paths move tokens with their slots.
- A live slot belongs to the caller: the allocation paths move its token into the block’s `heap::live::Live` token, which the entry points’ cores return (`Live::gives`) and the free cores take back (`Live::claims`). C callers carry no ghost state: the export hands the token to C with the block, and `heap::live::axiom_c_claim` gives the one C holds back when it frees the block.
- A live huge run has a `huge::RunToken`: its extent, a singleton of one authority, and its pages, a subset of another. `Inner::wf` holds both authorities, whose sets are the `Active` descriptors’ extents and pages; `Huge::take` inserts a new run’s and `Huge::free_run` deletes them, after `agree` shows the token’s extent is the descriptor’s. `huge::axiom_run_locs` assumes one huge allocator per process.
- `ClassState::release_owned` returns a batch’s distinct tokens to the bitmap words. A batch containing the same slot twice cannot supply the required tokens.

The bitmap word wrappers model each `fetch_or`, `fetch_and`, `store`, and the free path's `load` as one atomic step and preserve the caller’s machine-code ordering. Their proof specifications ignore that ordering and assume sequential consistency. `table::axiom_fresh_words` supplies the initial zero words, and `table::axiom_slot_loc` assumes one authority, and one guard geometry, per class per process. A guard slab's bits keep their fresh markers in their word invariants (`bitmap::guards_ok`), so they stay clear and no token of a guard-slab slot ever leaves its word.

The chain still stops at heap creation, unfollowed cache writers, and the C caller boundary. `Heap::create` and `create_detached` write empty headers through raw pointers; trusted accessors then assume `Heap::wf`. The live-block model connects the hand-out and the free, up to the C boundary’s `axiom_c_claim`; a proof of empty caches at creation would connect heap creation.
