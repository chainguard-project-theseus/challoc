- `GROUP_HANDOFF` stays in `mod.rs` rather than `handoff.rs` (commented at the static): the first cut put it in `handoff.rs` and the compare reported 7 changed functions, none in class (`api::init`, `api::fork_release`, `api::print::{advice_line, slice_line, malloc_stats_print}`, `purge::background::start`, plus `__aarch64_ldset8_acq` padding) and q8 `.text` 32 bytes smaller. The unmasked immediates showed every difference was a load or store off the AArch64 merged-globals blob in `.bss` whose anchor had moved 4 bytes (`#0xf64` -> `#0xf60`) with every member offset moving +4, flipping the `ldr`/`ldur` encoding and letting one `stp` fuse. A static's position among the crate's items fixes its slot in that blob, so the module's one release-mode static keeps its position; a `const` and the `#[cfg(test)]` counter do not matter and moved. Rule for the other batch-two lanes (`heap/`, `huge/`, `purge/`): keep every `static` in the file it was in (or in `mod.rs` of the new directory) and expect this signature if the compare reports cold `api`/`purge` functions changed after a split.

- `scripts/codegen-diff.sh`'s fingerprint is broken (tooling lane's file): `fingerprints()` prints the whole exact and masked instruction text and then `read -r n ex ma name` splits that text on whitespace, so `ex` is the first mnemonic (`|sub`), `ma` the second token (`sp,`) and `name` the rest of the line; the hashes are `cksum` of those two tokens and the report's "name" of a changed function is `sp,`. The compare therefore only matches functions on (instruction count, first mnemonic) and over-reports `exact` (435 exact / 0 reloc-only here, against a real 146 / 289). It still caught the 4-instruction change above because the count changed. Fix: compute the two checksums inside awk (or pipe each text through `cksum` per function) instead of splitting the printed line; a Python comparer that does this properly is left in this worktree as `.tmp-fncmp.py` (ignored by git) and prints a unified diff per changed function.
