## Design decisions

- Phase 3 task 4: the key table is in `KEYS` order, not grouped by topic, so a reader can diff it against `config.rs` and the `opt.` block of the report line by line; the topical reading is in the sections after it (consumers, cgroup, THP). One row per key with six columns; the reasons for the defaults are a list after the table rather than a seventh column, so the rows stay one line.
- Phase 3 task 4: every number in the guide is one read from a `bench/results/` file this iteration, and the file is named next to it. Where the README or design rounded a figure differently from the results file, the guide carries the file's figure: the `double_free_scan` cost is given as the x86_64 valkey1 medians (14.828 -> 13.004 M ops/s, `2026-09-18-x86_64-gce-detection-gaps.md`) rather than the README's "up to 14%"; the `thp:auto` small-heap cost as larson1's 15.9 -> 18.1 MiB (`2026-09-19-lane-b-mthp.md`) rather than design 17's "7..19%"; the two-advice `pglazyfree` rise as 188 MiB (the file) rather than design 8's 189.
- Phase 3 task 4: the Ruby section says "nothing to set" as the task asked and records the `narenas:1` soak finding as a packaging option not taken, with the caveat that one arena's contention was not measured; it does not recommend it. The JVM and Node sections record the rows and name the one knob each row points at (`narenas` as the `MALLOC_ARENA_MAX` analogue, `huge_retain_max` for Node's 1 MiB buffers) without recommending a value, since no lower value was measured.
- Phase 3 task 4: the report-reading section quotes the exact strings the code prints (the `Prefault:` forms including the `taken N` tail, the `Per-CPU caches:` probe words, the six `purge advice:` reasons, the `thp:` reason texts) rather than paraphrasing design 16, so an operator can grep a report for them.
