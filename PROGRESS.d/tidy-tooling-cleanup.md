## Notes for the human

- The amd64 image was not built (emulated, slow): the Dockerfile split is verified on arm64 only. The package set is architecture-independent apart from what apk resolves, so a `make image PLATFORM=linux/amd64` on the amd64 VM is the one check left.
- challoc-bench was not run against GCE (this lane created no VMs): the matrix_fail/matrix_oslogin refactor is `bash -n` clean and read against every call site, but a real `matrix` run (a `k61-amd64` cell is the cheapest, about 20 minutes) is the check left. The PENDING line no longer carries a `zones=` field; the zones tried are in the cell's `cell ...: zones` driver line above it.
- No `make lint`: `shellcheck` is not in Wolfi (`apk search shellcheck` is empty) and not on the host either, so the target and the `.shellcheckrc` were not added; the quoting fixes are the by-hand ones in the two sidecars. If shellcheck is wanted, a `koalaman/shellcheck` container image is the route.
- The residual before/after differences in the harness results are measured: node's "RSS by mapping name" list is ordered by size, so two runs order libicuuc/libicui18n and node/[heap] differently; postgres's connect20 per-backend columns read `-` when the sampler caught no backend in a 2 s row. The soak's percentage signs flip run to run on a loaded Mac.
- `bench/gce/drun.sh` lets `IMAGE=` override the image name for quick-perf.sh and perf-record.sh (it used to be fixed at challoc-dev:$T); an `IMAGE=...` argument to quick-perf.sh is now honored.
- The harness runner used here (`.tmp-harness-run.sh`, ignored) hit a pre-existing hazard worth knowing: a harness that dies while its server is up (node-bench's `ab` warm-up refused `-c 32 -n 10`) leaves the server holding target/bench.lock through the inherited fd 9, and the next harness in the same container refuses to start. Killing the orphan frees it; a `trap` in the harnesses would be the fix, outside this lane's files.
- Ruby was the one harness not exercised end to end (no `make ruby STAGE=build` in this volume); the lane's ruby-bench.sh change is limited to `record_rt`, `check_score_lines`, `result_header` and the jemalloc describe line, all shown equivalent elsewhere.
