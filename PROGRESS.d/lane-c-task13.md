- Phase 2.5 task 13 DONE (lane C, 2026-09-19): `src/model.rs`, test-only (`#[cfg(test)] mod model;` in `lib.rs`), an explicit-state model checker on stable Rust with no dependency, run by `cargo test --features std model::`. One class, two slabs of four slots, one or two arenas, two or three threads. Shared state: per slab the state byte, `live`, the bitmap word, the descriptor arena and the slot memory (a dirty bit per slot); per arena the class lock, the partial/empty/purged sets and the group cursor; the owner word per group and the class-wide next group. Operations mirror `class.rs` step by step with the lines quoted: `Refill(n)` = lock, `plan_locked` (the partial walk with the full-slab `clear_partial`, `next_slab`: empty, purged, the group cursor, `adopt_idle_group`/`transfer_group` with `group_handoff`, `take_group`; `take` with `add_live`, the partial bit rule, the zero flag and `claim_prefix`), unlock, then `finish` (`claim_word`'s `fetch_or` per step, waiting on a clear bit instead of `MAX_EMPTY_PASSES`), and the `claim_with` re-plan when short; `Write(i)`; `Release` = per slab `fetch_and` (double-free, guard/Fresh and owner checks), `sub_live`, `on_live_zero` (lock, owner check, `Active` with `live == 0` to `Empty`), then `reopen` (lock, `Active` and owner) for full words; `Purge` = lock, every `Empty` slab to `Purged` and its memory to zero. DFS over every interleaving, memoised on the whole state (`HashSet<Node>`), invariants at every state: no slot held by two threads, a held slot's bit set, a slot reported zero and unwritten reads zero, `live == popcount(bits) + reservations in flight + releases between fetch_and and sub_live`, a slab in at most one set and only its owner's, partial implies `Active`, `Empty`/`Purged` in exactly their owner's set with `live 0` and no bits (`Purged` and `Fresh` read zero), descriptor arena equals the owner word; a protocol abort (`zero_slab_had_bits_set`, `double_free`, `idle_group_in_use`, underflow) and a deadlock are violations too. ## Design decisions

- Form (a), an explicit-state checker, not `loom`. Reason: `loom` would need the real `ClassState` compiled against its atomics and locks (a `src/class.rs` change) and cannot express the pre-fix step order; the model is written against the real code's step order with the lines quoted, so a protocol change is a model change.
- Lock holds that touch only lock-protected state are one atomic step; `fetch_or`, `fetch_and`, `sub_live` and the memory write are one step each and interleave with anything, including another thread's lock hold. `add_live` and `claim_prefix` are folded into `take`'s step. Reason: those are the only lock-free steps of the protocol, and the folded reads have no contender the code relies on; stated in the module docs.
- `finish` waits for a clear bit instead of spinning `MAX_EMPTY_PASSES`; an unmet reservation therefore shows as a deadlock violation. Reason: a self-loop would not terminate the DFS; the accounting invariant already guarantees a bit exists.
- `Write(i)` past a short refill is a no-op. Reason: a program writes what it was given; with eight slots and three threads a `Refill(3)` can come up short, and that is the scenario, not a bug.
- The handoff is modelled as part of `Refill`'s locked step (as in `next_slab`), with `try_lock` skipping a held donor. Reason: that is where the real code does it, and it made the task 15 ownership gap reproducible.

## Notes for the human

- The model found nothing new in the current protocol; its value is the two replayed regressions and that the next protocol change (per-CPU caches, task 8; the two-advice purge, task 10) has a place to be checked before the VMs. Scenarios are a few lines each (`calloc_race`, `churn`, `handoff`, `three_way`).
- State space grows fast with a third thread and long programs: keep programs to three or four operations with three threads, or two threads with six; the `MAX_STATES` assert names the case.
- Not modelled: page groups (`spp > 1`), guard slabs, `slot_randomize`, the thread cache and `Heap::flush` above `claim`/`release`, the decay curve. The page-group purge (`page_group_is_idle`) is the one of these on a lock-held path and could join the model with `NSLABS = 4` and `spp = 2`.
